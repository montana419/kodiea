1. Sepolia (EVM Testnet)

Identity & Authorization

Role: EMT Credential Registry

What it does: Sepolia hosts the smart contract that issues ERC-721 EMT Badges / Licenses to verified medical personnel.

How it links: Before the terminal decrypts any sensitive patient data, it queries Sepolia using the paramedic's wallet address (0x...). If balanceOf(paramedicAddress) > 0, the paramedic is confirmed as an active, credentialed first responder. If they do not hold a valid token on Sepolia, access is blocked.

Token: ERC-721 EMT Badge
Chain: Sepolia Testnet
Validation: balanceOf(address) > 0

2. IPFS / Attestation ("AttesCoin")

Data Storage & Integrity

Role: Decentralized Storage & Verification Layer

What it does: Stores encrypted patient medical profiles (allergies, blood type, conditions, emergency contacts) off-chain using immutable Content Identifiers (CIDs).

How it links: The physical QR code on the wristband or phone sticker maps directly to an IPFS CID. Once Sepolia approves the paramedic’s authorization, the system uses the CID embedded in the scanned barcode to fetch and decrypt the medical payload directly from the IPFS network.

CID Format: Base58 / v1 JSON
Encryption: AES-256 Payload
Access: Gateway Sync

3. Creditcoin

Cryptographic Audit Trail

Role: Immutable Access Logging

What it does: Serves as a dedicated layer for recording non-repudiable audit receipts of cross-chain or off-chain data requests.

How it links: Every time a record lookup is performed in the field, the terminal hashes the request details:

Receipt Hash = SHA-256(IPFS CID + Paramedic Wallet + Timestamp)

This 32-byte hash is recorded on the Creditcoin ledger, creating a permanent, tamper-proof audit trail proving who accessed which patient file and when, preventing unauthorized data leaks or unauthorized scans.

Receipt: SHA-256 Hash
Audit Log: Creditcoin L1 Ledger
Integrity: Non-repudiable
